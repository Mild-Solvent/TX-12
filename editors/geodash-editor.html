Tune text (m)

Format (from phys.lua): tokens separated by spaces. A note is <letter>[#]<octave digit><length digit>, e.g. C42 = C4 for 2 units, A#31 = A#3 for 1 unit. R<n> = rest of n units. One unit lasts u seconds. The tune loops and restarts with every attempt. Sharps only (no flats). Anything else plays as a 1-unit rest on the radio.
Piano roll (like FL Studio): one column = one unit (thin lines), a beat = 4 units, a bar = 16 units (numbered). Left click an empty cell places a note with the current length (click again on it to hear it), left drag a note moves it in time and pitch, drag its right edge to change its length, right click (or right drag across notes) deletes. Shift/Ctrl+drag = box select (Shift adds), or switch to Select mode so a plain drag box-selects. Clicking the roll also moves the yellow cursor: Paste, Insert bar and ▶ from cursor work from there. The buttons above the roll do cut / copy / paste / duplicate / transpose / stretch / reverse / legato on the selected notes. With the roll focused: Ctrl+X cut, Ctrl+D duplicate, Del deletes the selection, Ctrl+C/Ctrl+V copy / paste at the mouse, Ctrl+A selects all, arrows move the selection (Shift = octave), Ctrl+wheel on a note = length. The tune is one voice: a note placed over others cuts them. Gaps are written as rests; notes longer than 9 units as tied notes (C49 C43). The red line is the loop end. Click the keyboard on the left to hear a pitch.
Putting it on the radio
  1. Copy the file to the SD card as /SCRIPTS/GAMES/GDASH/L9.lua.
  2. Delete any L9.luac next to it, or the radio keeps running the old compiled copy.
  3. The game finds levels by counting L1.lua, L2.lua, ... until one is missing (max 99). To add a level, save it as the next free number (L9.lua, L10.lua, ...) — no game change needed. A gap (e.g. L9 missing, L10 present) hides every level after the gap.
  4. The first line -- @Name|Difficulty is the name and difficulty shown in the picker. The radio reads only the first 80 bytes, so keep that line short; no | in the name.
  5. Best % and attempts are stored per level number in /SCRIPTS/GAMES/gdash.dat; replacing a level keeps its old record.

Tiles (characters as stored in the level file)

How a level file works

  • 6 to 20 strings, bottom (ground) row first. Column c is 8 px wide; the cube (7×7) starts at x = 0 on the ground at speed 2 (90 px/s), cube mode, normal gravity.
  • Taller levels: 6 rows fill one radio screen. Set Height up to 20 rows and the radio's camera scrolls up and down to follow the icon (the editor shows a dashed line where the first screen ends). The game counts the rows, so every row is written, even empty ones. One real Geometry Dash block = one tile: speed 2 (90 px/s, 11 tiles/s) is close to the real normal speed, so real levels keep their length and height.
  • Slopes (/ ` () []): solid under the diagonal. With normal gravity the icon slides along them, leaves an up slope into the air with its climb speed, and dies running into a high side (a ` seen from the left, a lone ) or [). With flipped gravity only their flat bottom counts, like a block's.
  • The level ends at x = (longest row length) × 8 + 16, so trailing empty columns in row 1 make the level longer. The editor keeps row 1 full length and trims the other rows, like tools/gdash/build.js.
  • Portals act on the whole column: when the icon's centre enters the column, every portal in it fires once, whatever its row. You may stack several portals in one column (e.g. D + W = dual wave, U + G = upside-down UFO).
  • Compact rows: a run of 4 or more equal tiles is written c*N, where N is one character whose code minus 32 is the count (.*D = 36 dots). The game keeps the rows coded in memory and decodes only the 128 columns around the icon, so a long level costs about its file size in RAM. Old files with plain rows still load; tick plain rows on the Export tab to write them plain.
  • The first line -- @Name|Difficulty is what the level picker shows (the editor reads it on import and always writes it).
  • Adding a level: save it as the next free number, L9.lua, L10.lua, ... in /SCRIPTS/GAMES/GDASH/ — no game change needed. The game counts L1, L2, ... until one is missing (max 99). Delete any old .luac of the same name.

Editor controls

  • Left drag paints the selected tile, right drag erases. Painting past the end makes the level longer.
  • Type a tile's character to pick it (the character in the palette, e.g. # ^ o S W; . = empty). Upper and lower case are different tiles.
  • Shift+drag (or the Select tool) selects. Ctrl+C/X/V copy / cut / paste (paste puts the bottom-left corner on the cell under the mouse), Del clears, Esc deselects.
  • Ctrl+Z undo, Ctrl+Y / Ctrl+Shift+Z redo. Mouse wheel scrolls sideways.
  • Insert cols / Delete cols work on the selection's columns, or on N columns at the mouse.
  • The level is saved in this browser automatically (draft), but only Download gives you a file.
  • Check beatable before exporting. Tight presses (window under ~60 ms) are flagged red; the radio runs at 20-80 ms per frame, so those are very hard.

Seconds shown

"run" = time for the icon to reach the end following the speed portals (exact, since speed does not depend on input). Also listed: the time at each constant speed 0-4.

Mini (m): 5×5 icon, jumps/orbs/pads x0.8, ship and swing accelerate x1.25, wave twice as steep. Every icon is drawn upside down with flipped gravity. Flying modes (ufo, ship, wave, swing) use the whole field (all rows) as their corridor: the ceiling line turns solid while you fly. Make a narrower corridor with blocks. Speeds: 0 = 50, 1 = 70, 2 = 90, 3 = 110, 4 = 130 px/s.

Radio timing: SA/SD are read once per frame (20-80 ms), so a hold is as exact as one frame and a "tap" may last a whole frame (robot: a tap on a slow 80 ms frame jumps ~20 px, not 12). ENTER is a tap only: it cannot hold a ship, wave or dash orb.
